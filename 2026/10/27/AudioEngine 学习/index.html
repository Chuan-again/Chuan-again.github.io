三、AudioEngine 启动流程

主要做了以下几步：

  1. 首先做 csd2_init()，完成 csd2 驱动库初始化。
  2. 创建 9 个 service 并调用 addService()：Chime / BootMusic / DriveMode / Avas / Eol 等，AudioEngine::addService 将其存入 mServices。
  3. 调用 AudioEngineServer::getInstance()，启动 mqueue IPC 接收。
  4. 调用 engine->ready()，置 mIsReady=true，向全部 listener 广播 PLAY_STATE_READY。

五、QNX QSA 音频栈

接下来讲一下 io-audio。在我的项目上 AVAS 都是通过 io-audio 进行播放的，io-audio 接口再与 QC 的 deva 进行交互，最后 deva 再调用 CSD2 的接口，进行流的播放控制。

QSA（QNX Sound Architecture） 是 QNX Neutrino 的音频子系统，官方入口页给出的三大关键组件就是它的骨架：

组件 角色
io-audio Audio system manager(音频系统管理器/资源管理器进程)
deva-ctrl-*.so 音频驱动插件(如 deva-ctrl-audiopci.so),由 io-audio 动态加载
libasound.so + <sys/asound.h> / <sys/asoundlib.h> 应用编程接口库与头文件

分层结构：

项目上 QNX 的声卡相关设备：

produce or capture 声音所需的基本硬件是音频芯片或声卡，简称为卡。QSA 一次可以支持多个卡，甚至可以“动态地”挂载和卸载卡（稍后会详细介绍）。所有的声音设备都连接到一张卡上，所以为了接触到设备，你必须首先知道它连接到哪张卡上。

Control 控制设备：系统中的每个声卡都有一个控制装置。

这个设备很特别，因为它不直接控制任何实际的硬件。它是卡和卡上其他设备信息的集中点。控制装置保存的主要信息包括附加到卡上的附加装置的类型和数量。

看下常用接口及其作用：

其中的 status 使用的比较多，表示状态流。在播放过程中，会通过该接口获取当前流的播放状态，以便进行下一步操作。

snd_mixer_open()：Create a connection and handle to a specified mixer device。

snd_mixer_open() 调用返回一个混合器句柄，您将使用它作为应用于此设备的其他 API 调用的参数。它是一个指向 snd_mixer_t 结构的指针，这是一个不透明的数据类型。

要读取一个混音组，请调用 snd_mixer_group_read() 函数。该函数的参数为混音器句柄和组控制结构。组控制结构的类型为 snd_mixer_group_t；要读取特定的混音组，必须在调用前先在 gid 子结构中设置其名称和索引（参见 snd_mixer_gid_t）。如果调用 snd_mixer_group_read() 成功，该函数将向结构体中填充该组的能力信息和当前设置。现在你已经获得了组的特性及当前设置，可以在将这些设置写回混音器组之前对其进行修改。要将更改写入混音器组，请调用 snd_mixer_group_write() 函数，并传入混音器句柄和组控制结构作为参数。

snd_mixer_group_read() / snd_mixer_group_write() 会使用通过 snd_pcm_plugin_setup() 获取的 mSetup，该组反应了对应 pcm 节点的最佳 mixer group，用于音量相关控制工作。

snd_pcm_channel_params_t：通过该结构体设置播放参数的时候要计算 frag_size 的大小。这里是根据输出的参数计算出来的值赋值给了 frag_size，frag_size 表示 fragment 的大小（单位：字节）。

六、io-audio 播放通路与 deva 驱动

概念定义：io-audio 的 PCM 节点是 io-audio 进程启动时 dlopen 的 deva-ctrl-qc-ar.so 在 ctrl_init 里遍历设备表、经 ado_pcm_create 逐个注册到 /dev/snd/；每个节点的“后端”由 device_id → graph_map → csd2_graph_info 决定，本平台全部节点（含 avas）最终经 csd2 走 ADSP 的 TDM 端口出硬件。
